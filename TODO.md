- [ ] **`workspace.yml`, when a second repo publishes several npm packages.** Today one repo does ([ts-utils](https://github.com/adriangalilea/ts-utils): utils, llm, bot, metrics under `packages/`), and its `release.yml` holds a hand-written build, publish and release chain per package. Read at a glance, so it stays until there is a second case. Then: a `workspace.yml` that discovers `packages/*/package.json`, builds and packs each one under its own artifact, and returns the list of packages whose version has no GitHub release yet; the caller publishes each entry with `actions/npm-publish` (publishing stays in the caller's job: npm trusted publishing names the caller's workflow file and environment), and one release job per entry. Two traps it must avoid. A matrix of `node.yml` calls: a reusable workflow's outputs from matrix legs overwrite each other, and those outputs decide each package's publish. A matrix publish job with the releases after it: `needs` waits on the whole matrix, so one package's failed publish skips every package's release (ts-utils' first run did exactly that).
